Data link layer: MAC addresses, ARP, Ethernet, CSMA/CD

The link layer moves a frame across one hop, from one device to the next on the same network, using MAC addresses.

MAC addresses

  • A MAC address is a 48-bit hardware address built into every network card, written as 12 hex digits: 00:1A:2B:3C:4D:5E.
  • The first 24 bits identify the manufacturer; the last 24 are the card's serial number.
  • It is used only within one local network. It changes at every hop; the IP address stays the same end to end.

ARP — Address Resolution Protocol

To send a frame to a device on the same network, you need its MAC address, but you only know its IP. ARP translates IP address → MAC address.

Host A (wants 192.168.1.5)Everyone on the LAN
ARP request (broadcast)"Who has 192.168.1.5? Tell 192.168.1.2."
ARP reply (unicast, from the owner only)"192.168.1.5 is at 00:1A:2B:3C:4D:5E."
A stores the answer in its ARP cache and sends the frame

If the destination is on another network, the host ARPs for its default gateway's MAC instead and sends the frame to the router. View your cache with arp -a.

DNS: name → IP address. ARP: IP address → MAC address. DHCP: gives a device its IP address in the first place.

Ethernet and framing

Framing means wrapping a datagram with a header and trailer so the receiver knows where a frame starts and ends.

CSMA/CD — sharing one wire

On a shared wire (old Ethernet with hubs), two devices sending at once cause a collision. Ethernet's rule is CSMA/CD: Carrier Sense Multiple Access with Collision Detection.

  1. Carrier sense: listen first. If the wire is busy, wait.
  2. Transmit when it is idle, and keep listening while sending.
  3. Collision detect: if you hear another signal mixed with yours, stop at once and send a short jam signal so everyone knows.
  4. Back off: wait a random time, then try again. After each repeated collision the random range doubles (binary exponential backoff).

A polite dinner conversation: wait for silence before speaking; if two people start together, both stop and each waits a random moment before trying again.

Modern switched Ethernet is full-duplex with one device per port, so collisions no longer happen and CSMA/CD is rarely active. It is still examined.

Check yourself

How long is a MAC address and how is it written?

48 bits, as 12 hexadecimal digits in six pairs.

What does ARP do, and which message is a broadcast?

It finds the MAC address for a known IP address. The request is a broadcast; the reply is unicast.

What does a station do when it detects a collision in CSMA/CD?

Stops transmitting, sends a jam signal, waits a random backoff time, and retries.

As a packet crosses three routers, which changes at each hop: the MAC addresses or the IP addresses?

The MAC addresses (a new frame for each link). The source and destination IP addresses stay the same (unless NAT is involved).

WiFi: 802.11 standards, CSMA/CA, WPA2/WPA3

WiFi cannot hear collisions the way a wire can, so instead of detecting them it tries hard to avoid them.

CSMA/CA — collision avoidance

A radio cannot listen while it transmits (its own signal drowns everything), and two stations may both reach the access point but not hear each other (the hidden terminal problem). So collision detection is impossible; WiFi uses collision avoidance.

  1. Listen. If the channel is idle, wait a short fixed time, then also wait a random backoff before sending.
  2. Send the whole frame (no stopping midway).
  3. The receiver replies with a link-layer ACK. No ACK → assume a collision → back off longer and re-send.
  4. Optional RTS/CTS: send a small "Request To Send"; the access point answers "Clear To Send", which every station hears, so the others stay quiet. This solves hidden terminals.

Error detection: parity, checksum, CRC

The sender adds a few extra bits computed from the data; the receiver recomputes them, and a mismatch means the data was damaged.

MethodHowStrengthUsed in
Parity bitAdd one bit so the total number of 1s is even (or odd)Catches any odd number of flipped bits; misses an even numberSimple serial links
ChecksumAdd the data as numbers, send the complement of the sum (see Lecture 10)ModerateIP, TCP, UDP
CRCTreat the data as a binary number, divide by an agreed generator, send the remainderStrong; catches bursts of errorsEthernet, WiFi (link layer)

CRC step by step

  1. Sender and receiver agree on a generator G of r + 1 bits.
  2. Append r zeros to the data.
  3. Divide by G using modulo-2 division: subtraction is XOR, with no carries or borrows.
  4. The remainder (r bits) is the CRC. Send data + CRC.
  5. The receiver divides what it got by G. Remainder 0 → accept. Anything else → error.

G has 4 bits, so r = 3. Append three zeros: 100100000.

Transmit 100100001 (data 100100 + CRC 001). The receiver divides 100100001 by 1101 and gets remainder 000 → no error.

XOR rule: same bits → 0, different bits → 1. Divide (XOR with G) only when the leading bit is 1.

Physical layer: media, encoding, Shannon capacity

The physical layer turns bits into signals on a medium, and physics sets a hard upper limit on how many bits per second a channel can carry.

Coaxial cableElectrical signalsBetter shieldingBulky
Optical fibreLight pulsesHuge capacity, long distance, immune to electrical noiseCostly to install and join

Line encoding: bits → signal

SchemeRuleNote
NRZ1 = high level, 0 = low levelSimple, but a long run of the same bit gives no changes, so the receiver's clock drifts
NRZI1 = change level, 0 = no changeFixes long runs of 1s, not of 0s
ManchesterEvery bit has a transition in the middle (e.g. 0 = high→low, 1 = low→high)Self-clocking, but needs twice the bandwidth. Used in classic Ethernet.

Channel capacity

Nyquist (a noiseless channel): with bandwidth B hertz and M signal levels,

C = 2 · B · log₂(M) bits per second

Shannon (a real, noisy channel): the absolute maximum error-free rate is

C = B · log₂(1 + S/N) bits per secondB = bandwidth in Hz · S/N = signal-to-noise ratio as a plain ratio, not in dB

SNR is usually given in decibels. Convert first: SNRdB = 10 · log₁₀(S/N), so 10 dB = 10, 20 dB = 100, 30 dB = 1,000.

A telephone line has B = 3,000 Hz and SNR = 30 dB. Maximum data rate?

30 dB → S/N = 1,000. C = 3,000 × log₂(1,001) ≈ 3,000 × 9.97 ≈ 29,900 bps (about 30 kbps).

Nyquist on the same line with 4 signal levels and no noise: C = 2 × 3,000 × log₂(4) = 6,000 × 2 = 12,000 bps.

The lesson: to go faster you need more bandwidth or a better signal-to-noise ratio. No clever protocol can beat Shannon's limit.

Cloud at scale: peering, Transit Gateway, endpoints, hybrid links, CloudFront

One VPC is an island; these services are the bridges between VPCs, to AWS services, and to your own data centre.

ServiceConnectsKey facts
VPC PeeringTwo VPCs, directlyOne-to-one and private. Not transitive: if A–B and B–C are peered, A still cannot reach C. CIDR blocks must not overlap. Add routes on both sides.
Transit GatewayMany VPCs (and VPNs) through one hubHub-and-spoke. Each VPC attaches once to the hub instead of peering with every other VPC.
VPC EndpointsA VPC to AWS services (S3, DynamoDB…) privatelyTraffic stays on the AWS network; no IGW or NAT needed. Gateway endpoints (S3, DynamoDB) are a route-table entry; interface endpoints are a private IP in your subnet.
Site-to-Site VPNYour data centre to a VPC, over the InternetEncrypted IPSec tunnels. Quick and cheap; speed depends on the Internet.
Direct ConnectYour data centre to AWS, over a dedicated private lineDoes not use the public Internet. Steady, fast, low latency; costly and takes weeks to install.

Fully connecting 10 VPCs with peering needs 10 × 9 / 2 = 45 peering connections. With a Transit Gateway it is 10 attachments. This is the same reasoning that took us from full mesh to star in Lecture 4.

Hybrid cloud means part of the system runs in your own data centre and part in the cloud, linked by a Site-to-Site VPN or Direct Connect.

CloudFront deep dive

  • Edge caching: CloudFront keeps copies at Edge Locations. A request is served from the edge on a cache hit, and fetched from the origin (S3, ALB, EC2) on a miss. The TTL comes from Cache-Control or the cache policy. See CDNs.
  • Origin failover: put a primary and a secondary origin in an origin group. If the primary returns errors (such as 5xx) or times out, CloudFront automatically retries the request on the secondary.
  • Invalidation: removes an object from the edges before its TTL ends, when you must replace it immediately.
  • CloudFront also terminates TLS at the edge (ACM certificate) and can attach AWS WAF and Shield.

Check yourself

VPC A is peered with B, and B with C. Can A talk to C?

No. Peering is not transitive. A and C need their own peering connection, or all three attach to a Transit Gateway.

How do instances in a private subnet reach S3 without a NAT Gateway?

Through a VPC endpoint for S3 (a gateway endpoint).

Site-to-Site VPN vs Direct Connect in one line each.

VPN: encrypted tunnel over the public Internet, quick and cheap. Direct Connect: a dedicated private line, steady and fast but costly and slow to set up.

What is CloudFront origin failover?

An origin group with a primary and a secondary origin; CloudFront switches to the secondary when the primary fails.
