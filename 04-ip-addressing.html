Lecture 13 — IPv4 addressing, classful history, and CIDR

An IPv4 address is 32 bits split into two parts: the first part names the network, the rest names one device on it. CIDR lets you put that split wherever you need.

What is an IP address?

An IP address is a unique identifier given to each device on the Internet or a local network. "IP" stands for Internet Protocol, the set of rules for sending data between devices on networks.

Think of an IPv4 address as a four-part postal code: [Country].[State].[City].[Street number]. The left part gets you to the right area; the right part finds the exact house.

The format: 32 bits, dotted decimal

  • An IPv4 address is a 32-bit number.
  • It is written as four 8-bit numbers (called octets) separated by dots: 192.168.1.10. This is dotted-decimal notation.
  • Each octet is 8 bits, so it ranges from 0 to 255.
  • Total possible addresses: 232 ≈ 4.3 billion.
11000000 . 10101000 . 00000001 . 00001010

The 8 bit positions in an octet are worth:

Value1286432168421

168 → binary: take the values that fit, left to right. 168 − 128 = 40 → 1. 64 does not fit → 0. 40 − 32 = 8 → 1. 16 no → 0. 8 − 8 = 0 → 1. Rest 0. Result: 10101000.

11000000 → decimal: 128 + 64 = 192.

Network portion + host portion

Every IP address has two parts:

  • The network portion (network ID): the same for every device on that network. Routers use this part to reach the right network.
  • The host portion (host ID): different for each device on the network.

Example from class: in 172.16.1.10 (a class B address), 172.16 is the network ID and 1.10 is the host ID. The whole question of this lecture is: where is the dividing line?

Classful addressing (history)

Originally the dividing line could be in only three places, fixed by the first few bits of the address.

A city divided into three zones: A = massive districts for giant developments, B = medium districts for mid-sized projects, C = small plots for local use.

Why classful addressing was abandoned

  • Wasted address space. The jump between sizes is enormous: 254 → 65,534 → 16.7 million. A company needing 500 addresses could not use a Class C (too small, 254). It had to take a Class B with over 65,000 addresses and waste the rest.
  • Networks too big to manage. A flat Class A network has 16,777,216 addresses: far too many devices for one router.
  • The Internet grew faster than anyone predicted. Addresses were running out. In 2025 a public IPv4 address costs roughly $20–$45 to buy.

The fix: make addressing classless.

CIDR — Classless Inter-Domain Routing

CIDR (say "cider") replaces the A/B/C system. The dividing line between network and host can be placed after any number of bits, so a network can be sized to what is actually needed.

a.b.c.d / na normal IP address, a slash, then the prefix length n = how many of the 32 bits are the network portion

Example: 192.168.0.1/24 means the first 24 bits are the network portion and the remaining 32 − 24 = 8 bits are the host portion.

Given any address/prefix: find network, broadcast, and range

A method that works every time, without writing out binary.

  1. Find the "interesting" octet: the one where the mask is neither 255 nor 0. (/25–/30 → 4th octet. /17–/23 → 3rd octet. /9–/15 → 2nd.)
  2. Block size = 256 − mask value in that octet. (Class calls this the magic number.) Networks start at multiples of the block size.
  3. Network address: round the interesting octet down to a multiple of the block size; set all octets to its right to 0.
  4. Broadcast address: interesting octet = network value + block size − 1; set all octets to its right to 255.
  5. Usable range: network + 1 up to broadcast − 1.

Mask for /26 = 255.255.255.192 → interesting octet is the 4th. Block size = 256 − 192 = 64. Blocks start at 0, 64, 128, 192.

130 falls in the block starting at 128.

Network = 192.168.1.128 · Broadcast = 128 + 64 − 1 = 192.168.1.191 · Usable = 192.168.1.129 – 192.168.1.190 · Hosts = 2⁶ − 2 = 62.

Mask for /22 = 255.255.252.0 → interesting octet is the 3rd. Block size = 256 − 252 = 4. Blocks: 0, 4, 8, 12…

The 3rd octet is 5, which falls in the block starting at 4.

Network = 172.16.4.0 · Broadcast = 172.16.7.255 (4 + 4 − 1 = 7, then 255) · Usable = 172.16.4.1 – 172.16.7.254 · Hosts = 2¹⁰ − 2 = 1,022.

Private address ranges (RFC 1918)

Private IP addresses are for use inside local networks (homes, offices, VPCs). They are not routable on the public Internet, so the same range can be reused in every network. Your laptop at home may be 192.168.1.10, and a student in another city may also be 192.168.1.10. Both are valid because they are in separate private networks.

Range (CIDR)From – toAddressesOld class

Watch the middle one: it is 172.16 to 172.31, not all of 172.x. So 172.20.5.1 is private; 172.40.5.1 is public.

A device with a private address reaches the Internet through NAT, which swaps the private address for a public one (Lecture 15). Two more special addresses: 127.0.0.1 is loopback ("this computer itself"), and 0.0.0.0/0 means "every address" (used as the default route).

When you create a VPC you give it a CIDR block, usually from a private range. Subnets carve that block into smaller pieces.

VPC 10.0.0.0/16 — host bits = 16 → 2¹⁶ = 65,536 addresses
Subnet 10.0.1.0/24host bits = 8 → 256 addresses
Subnet 10.0.2.0/24256 addresses

From the class demo in the console: the lab VPC is 10.0.0.0/16, with subnets such as 10.0.0.0/20 and 10.0.144.0/20. A /20 has 2¹² = 4,096 addresses, and the console shows 4,091 available, because AWS keeps 5 for itself (see Lecture 14).

Lecture 14 — Subnetting in practice, and designing an AWS VPC

Subnetting cuts one big network into smaller ones by moving the network/host line to the right: each borrowed bit doubles the number of subnets and halves their size.

Borrowing host bits

One large network is hard to manage and to secure. Subnetting means splitting it into smaller networks (subnets). We do it by borrowing bits from the host part and using them as extra network bits.

borrow k host bits → 2k subnets, each with 2(host bits left) − 2 usable hosts

On the quick-reference sheet Subnets from borrowed bits = 2k.

10.0.0.0/24 has 24 network bits and 8 host bits. We want 4 subnets. 2k = 4 → borrow k = 2 bits. New prefix = 24 + 2 = /26. Host bits left = 6 → 2⁶ − 2 = 62 usable hosts each.

24 network bits · 2 borrowed bits · 6 host bits
original network bits (24)borrowed bits (2) → 4 subnetshost bits left (6)

Magic-number shortcut: the /26 mask is 255.255.255.192. Magic number = 256 − 192 = 64. So the subnets start at .0, .64, .128, .192.

Public vs private subnets

Not every subnet should face the Internet.

  • A subnet is public because its route table has a path to the Internet Gateway: 0.0.0.0/0 → IGW.
  • A subnet is private if its route table does not send 0.0.0.0/0 to the Internet Gateway. It can still reach out through a NAT Gateway.

Public subnet → route table → IGW → Internet. Private subnet → route table → NAT → Internet (outbound only).

The 3-tier architecture

Public entry, private data. Only the web tier is reachable from outside. For availability, repeat the same tiers across at least 2 Availability Zones.

AWS size limits and subnet rules

  • A VPC or subnet IPv4 block must be between /16 (largest) and /28 (smallest). You cannot create a /29 or /30.
  • Subnets cannot overlap. 10.0.1.0/24 and 10.0.1.128/25 share addresses → not allowed.
  • A subnet must fit inside the VPC's CIDR. In VPC 10.0.0.0/16, 10.0.2.0/24 is valid; 10.1.0.0/16 is not.
  • You cannot change a subnet's size after creating it. If it is wrong, create a new subnet and move the resources. Plan the size up front.

Lecture 15 — NAT, PAT, DHCP, and VPC routing

NAT lets many private devices share one public address, DHCP hands out addresses automatically, and the route table decides where every packet goes next.

NAT — Network Address Translation

The puzzle from class: private addresses cannot be reached from the Internet, yet your phone on home WiFi has a private IP and loads every website. How?

NAT rewrites addresses at the border of the network (in your router).

  • On the way out: the router swaps the private source IP for its own public IP.
  • On the way back: it reverses the swap, restoring the private IP as the destination.
  • The reply finds its way home only because the router remembers the swap in a translation table.

PAT — Port Address Translation

Ten devices at home are streaming, scrolling, and gaming at once through a single public IP. How does the router know which reply belongs to which device?

PAT adds the port number to the translation, not just the IP. Each connection gets the same public IP but a different public port. This is exactly what your home router does every second. (PAT is also called NAT overload; when people say "NAT" they usually mean PAT.)

  • Conserves scarce public IPv4 addresses.
  • Hides internal hosts: a security side-effect.
  • End-to-end reachability is gone: outsiders cannot start a connection to an inside host.
  • Inbound connections need explicit setup (port forwarding).

DHCP — Dynamic Host Configuration Protocol

Nobody types IP settings by hand. When a device joins a network, DHCP configures it automatically. One DHCP lease delivers four things:

  1. IP address
  2. Subnet mask
  3. Default gateway (the router to use for everything outside the local network)
  4. DNS server

A lease expires, so addresses are renewed and recycled over time.

On the quick-reference sheet The four-step handshake: Discover → Offer → Request → Ack = DORA.

  • The Request is also broadcast so that any other DHCP servers learn their offers were not chosen.
  • DHCP runs over UDP: server port 67, client port 68.

Route tables and longest-prefix match

A route table is just a list: destination prefix → next hop. The router checks it for every single packet.

  • If several rows match, the most specific one wins: the one with the longest prefix. This is the longest-prefix match rule.
  • 0.0.0.0/0 is the default route: it matches everything, so it is used only when nothing more specific matches ("everything else goes here").
RouteMatches 10.0.1.55?Result

10.0.0.0/16Yes (first 16 bits match)Not chosen
10.0.1.0/24Yes (first 24 bits match)Winner: /24 is the longest

Specificity beats generality, every time.

  • Internet Gateway (IGW): attaches your VPC to the Internet. A public subnet routes 0.0.0.0/0 → IGW. Its instances can be reached both ways (if they have a public IP).
  • NAT Gateway: lives in a public subnet. A private subnet routes 0.0.0.0/0 → NAT GW. Instances can get updates out but stay unreachable from outside. "Updates flow out; attackers can't flow in."
  • Every route table also has a local route for the VPC's own range, so subnets inside the VPC can talk to each other.

Lecture 16 — Diagnostics with ICMP, and the move to IPv6

ICMP is how the network reports problems (ping and traceroute are built on it), and IPv6 is the real cure for running out of addresses.

ICMP — Internet Control Message Protocol

  • ICMP is IP's control and error channel. It carries control and error messages, never user data.
  • An ICMP message travels inside an IP datagram, but it is considered a network-layer helper.
  • A router that drops a packet can say why. Without that you would be blind.

ping — are you there?

Sends an Echo Request and waits for the Echo Reply. It tells you two things: the host is reachable, and the round-trip time (RTT).

$ ping -c 3 8.8.8.8
64 bytes from 8.8.8.8: icmp_seq=1 time=12.4 ms
64 bytes from 8.8.8.8: icmp_seq=2 time=11.8 ms
64 bytes from 8.8.8.8: icmp_seq=3 time=12.1 ms
rtt min/avg/max = 11.8/12.1/12.4 ms          ← reachable, about 12 ms away

$ ping 10.55.99.200
Request timed out.
3 packets sent, 0 received, 100% loss         ← nothing came back

A reply proves the host is reachable. Silence means the request went out and nothing came back. Note that silence can also mean a firewall is blocking ICMP, so it does not always prove the host is down.

traceroute — the TTL trick

Every IP packet has a TTL (Time To Live) number. Each router subtracts 1. When it reaches 0 the router drops the packet and sends back an ICMP Time Exceeded message. TTL exists to stop packets circling forever. Traceroute uses it on purpose: it sends packets designed to die and listens to who reports the death.

RoundTTL sentDies atWho replies "Time Exceeded"
11Router 1R1 → you now know hop 1
22Router 2R2 → hop 2
33Router 3R3 → hop 3
44—The server itself answers. Done.

Each round reveals one more router. Reading the output:

  • RTTs rise from hop to hop because each is farther away.
  • * * * means no reply: filtered or dropped, not always broken.
  • When troubleshooting, the last hop that responded is your prime suspect. If replies stop after hop 6, start investigating at or just after hop 6.

IPv6

The problem: IPv4's 32 bits give about 4.3 billion addresses, fewer than the number of people on Earth. NAT was a patch: it bought time but did not create addresses, and it hides hosts from the outside. IPv6 is the actual cure.

  • An IPv6 address is 128 bits.
  • Written as 8 groups of 4 hexadecimal digits (16 bits each), separated by colons.
  • Total: 2128 ≈ 3.4 × 1038 addresses. Enough for every device and sensor with room to spare.

Shortening an IPv6 address

StepRuleResult
Full2001:0db8:0000:0000:0000:0000:0000:0001
1Drop leading zeros in each group2001:db8:0:0:0:0:0:1
2Replace one run of all-zero groups with ::2001:db8::1

:: may appear only once in an address. With two of them, nobody could tell how many zero groups each one stands for.

ChangeMeaning
No NAT neededEnd-to-end addressing returns: every host can be directly reachable

AutoconfigurationA host can assign itself an address; no DHCP server required

Transition: living in a mixed world

The Internet cannot switch overnight, and NAT "worked well enough", so adoption is slow. Three transition mechanisms:

  • Dual stack: a device runs IPv4 and IPv6 together. It tries IPv6 first and falls back to IPv4. This is the main method.
  • Tunneling: wrap an IPv6 packet inside an IPv4 packet to cross a part of the network that only speaks IPv4.
  • Translation: convert between IPv6 and IPv4 at a gateway (e.g. NAT64).

An AWS VPC can take an IPv6 CIDR block alongside its IPv4 block (dual stack). Same subnetting thinking, far more room.

Check yourself

What is ICMP used for? Does it carry user data?

It carries control and error messages for IP (reachability, TTL expiry, unreachable destinations). It never carries user data.

Which ICMP messages does ping use? Which does traceroute rely on?

ping: Echo Request and Echo Reply. traceroute: Time Exceeded.

Explain the TTL trick in two sentences.

Traceroute sends packets with TTL 1, 2, 3… Each router decrements TTL; the router where it hits 0 drops the packet and returns an ICMP Time Exceeded, revealing itself as that hop.

A traceroute shows replies through hop 6 and then * * * to the end. Where do you look first?

At or just after hop 6, the last hop that replied.

Compress 2001:0db8:0000:0000:0000:ff00:0042:8329.

2001:db8::ff00:42:8329.

How many bits is an IPv6 address, and why can :: be used only once?

128 bits. Two :: would make it impossible to know how many zero groups each replaces.

What is dual stack?

Running IPv4 and IPv6 side by side on the same device or network, preferring IPv6 and falling back to IPv4.
