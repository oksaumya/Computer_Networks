Lecture 17 — Routing algorithms: link-state (Dijkstra) and distance-vector (Bellman-Ford)

Routers work out the cheapest path to every destination in one of two ways: everyone gets the full map and computes alone, or everyone trusts what their neighbours tell them.

Routing as a shortest-path problem

Model the network as a graph:

  • Nodes = routers. Edges = links. Edge weight = cost of the link (delay, hop count, or inverse of bandwidth).
  • Goal: each router finds the least-cost path to every destination.
  • Output: a forwarding table of destination → next hop. A router stores only the next hop, not the full path.

Google Maps does exactly this: intersections are nodes, roads are edges, live traffic time is the weight.

Link-state (global)Distance-vector (decentralised)
IdeaEveryone gets the whole map, then computes aloneNo map. Trust only your neighbours' reports.
AlgorithmDijkstraBellman-Ford

Link-state routing and Dijkstra

  1. Each router tells every other router about its own links and their costs (this is called flooding).
  2. Now every router holds the same complete map.
  3. Each router runs Dijkstra's algorithm on that map, with itself as the source.

Dijkstra in words: keep a set of visited nodes and a tentative distance for each node. Start with the source = 0 and everything else = ∞. Repeatedly pick the unvisited node with the smallest tentative distance, mark it visited, and relax its neighbours (if going through this node gives a shorter distance, update it).

The "Tracing Dijkstra" slide lists the result A→C = 1, A→B = 3, A→D = 4, A→E = 7 via A–C–B–D–E. Those numbers do not fit the graph drawn on the warm-up slide (where A–B = 1 and A–C = 4); they would fit a graph with A–C = 1, C–B = 2, B–D = 1, D–E = 3. The method is identical. In an exam, always trace on the graph you are given.

Link-state converges fast and has no loops, but costs more messages and more CPU and memory per router. OSPF uses it.

Distance-vector routing and Bellman-Ford

  • Each router knows only its direct neighbours and the cost to reach them.
  • Every router periodically sends its distance vector (its current list of "destination, cost") to its neighbours.
  • On receiving a neighbour's vector, a router updates its own with the Bellman-Ford rule, and repeats until nothing changes. No global map is ever built.
Dx(dest) = min over each neighbour n of [ cost(x, n) + Dn(dest) ]"my cost to a destination = the cheapest of (cost to reach a neighbour + that neighbour's cost to the destination)"

X's direct link to Z costs 7, so DX(Z) = 7. Then neighbour Y advertises DY(Z) = 1, and cost(X, Y) = 2.

DX(Z) = min(7, 2 + 1) = 3. X now routes to Z via Y. X never saw the X–Y–Z path; it just trusted Y's number.

Asking a local for directions in an unfamiliar town: no map, just their word plus the distance you still have to walk.

The count-to-infinity problem

"Good news travels fast, bad news crawls." Take a line A — B — C with cost 1 on each link. B reaches A at cost 1. C reaches A at cost 2, going via B.

  1. Link A–B fails. B should announce "A is unreachable".
  2. But C's old vector says "I can reach A at cost 2". B believes it and sets its cost to A = 2 + 1 = 3 (via C). C's route was through B itself, but B cannot know that.
  3. C hears B's new cost 3 and updates to 3 + 1 = 4.
  4. B hears 4 and updates to 5. And so on, each out-bidding the other, toward infinity.

Root cause: routers act on second-hand information without the full map. (Class analogy: a broken-telephone rumour repeated back to its source.)

The fix: split horizon and poisoned reverse

  • Split horizon: never advertise a route back to the neighbour you learned it from. C learned its route to A from B, so C does not tell B "I can reach A".
  • Poisoned reverse: go further and advertise it back with cost ∞, an explicit "don't use me". C → B: "A costs ∞".

This fixes the simple two-router loop. It does not solve every topology, but it is the standard first fix.

Check yourself

In routing, what do nodes, edges, and weights stand for?

Routers, links, and link costs (delay, hops, or inverse bandwidth).

X reaches Z directly at cost 10. Neighbour W (cost 3 away) advertises cost 4 to Z. Neighbour Y (cost 1 away) advertises cost 8. What is X's new cost and next hop?

min(10, 3 + 4 = 7, 1 + 8 = 9) = 7, via W.

What causes count-to-infinity?

After a link fails, a router accepts a neighbour's stale route that actually passes through itself. The two keep increasing their costs in turn.

Difference between split horizon and poisoned reverse?

Split horizon: say nothing about a route to the neighbour you learned it from. Poisoned reverse: advertise it back to that neighbour with infinite cost.

Which converges faster, and which is lighter on each router?

Link-state converges faster. Distance-vector is lighter.

Routing protocols: RIP, OSPF, BGP

The algorithms are the engines; the protocols are the real software that runs them. RIP and OSPF work inside one organisation, BGP connects organisations.

The Internet is divided into Autonomous Systems (AS): networks under one administration (an ISP, a university, Google). Routing inside an AS uses an interior protocol (IGP); routing between ASes uses an exterior protocol (EGP).

RIPOSPFBGP
Full nameRouting Information ProtocolOpen Shortest Path FirstBorder Gateway Protocol
TypeDistance-vectorLink-statePath-vector
AlgorithmBellman-FordDijkstraBest path chosen by policy
ScopeInside an AS (small networks)Inside an AS (large networks)Between ASes: "the Internet's glue"
MetricHop count (max 15; 16 = unreachable)Cost, usually based on link bandwidthAS path and business policies
UpdatesWhole table to neighbours every 30 sLink-state floods when something changesIncremental, over TCP port 179
ConvergenceSlowFastSlow but very scalable
  • RIP's 15-hop limit is its built-in answer to count-to-infinity: "infinity" is 16.
  • OSPF can split a big network into areas to keep the map small.
  • BGP advertises the whole list of ASes on the way to a destination (hence "path-vector"). A router that sees its own AS in the list rejects the route, so loops cannot form. BGP chooses routes by policy (who pays whom), not just shortest distance.

AWS route tables hide all of this: inside a VPC you write static routes (local, IGW, NAT) and AWS does the rest. BGP appears when you connect your own data centre using Direct Connect or a Site-to-Site VPN.

Check yourself

Which protocol is link-state, which is distance-vector, which is path-vector?

OSPF, RIP, BGP.

What is RIP's metric and its limit?

Hop count, maximum 15. 16 means unreachable.

Which protocol routes between Autonomous Systems?

BGP.

Firewalls: stateful vs stateless, Security Groups vs NACLs

A stateless firewall judges each packet alone; a stateful firewall remembers connections, so replies to traffic you allowed are let back in automatically.

Stateless filteringStateful filtering
Looks atEach packet by itself: source/destination IP, ports, protocolThe packet and the connection it belongs to (keeps a connection table)
Return trafficNeeds its own explicit ruleAllowed automatically if the outgoing request was allowed
Speed / memoryFaster, no memorySlightly more work, needs memory
SecurityWeaker: easy to leave return ports wide openStronger: only replies to real connections get in

AWS: Security Groups vs Network ACLs

AWS gives you two layers of defence.

Security Group (SG)Network ACL (NACL)
ProtectsAn instance (its network interface)A whole subnet
StateStatefulStateless
RulesAllow rules onlyAllow and deny rules
EvaluationAll rules are considered togetherRules are checked in number order; first match wins
Return trafficAutomaticMust be allowed explicitly (ephemeral ports 1024–65535)
DefaultDeny all inbound, allow all outboundThe default NACL allows everything

Web tier SG: allow 443 from anywhere. App tier SG: allow 8080 only from the web tier's security group. Database SG: allow 3306 only from the app tier's security group. A NACL on the database subnet can additionally deny a known bad IP range, which a security group cannot do.

VPC Flow Logs record metadata about traffic in your VPC: source and destination IP, ports, protocol, packet and byte counts, and whether it was ACCEPTed or REJECTed. They do not record packet contents. They go to CloudWatch Logs or S3 and are used to debug "why can't this reach that?" and to spot attacks. Think of them as a cloud-native, summary-level Wireshark.

Check yourself

An instance sends a request out and the reply is blocked. SG or NACL is the likely cause?

The NACL. It is stateless, so the inbound reply needs its own allow rule. A security group would let the reply in automatically.

You must block one specific IP address. SG or NACL?

NACL. Security groups have no deny rules.

What does "stateful" mean for a firewall?

It tracks connections, so traffic that is part of an allowed connection (such as the reply) is permitted without a separate rule.

Encryption recap, common attacks, and AWS protections

Most attacks either listen in, lie about an address, or flood the target; each has a standard defence.

TLS, certificate chains, symmetric vs asymmetric encryption are covered in full in Lecture 6. The cloud piece: AWS Certificate Manager (ACM) gives free public TLS certificates with automatic renewal; you attach one to an ALB and add an HTTPS listener on port 443.

VPNs: IPSec, OpenVPN, WireGuard

A VPN builds an encrypted tunnel across the public Internet, so two private networks (or you and your office) can talk as if joined by a private cable.

A VPN (Virtual Private Network) takes each packet, encrypts it, and wraps it inside another packet addressed to the VPN server (tunneling: encapsulation again). Anyone in between sees only scrambled data going to the VPN server.
