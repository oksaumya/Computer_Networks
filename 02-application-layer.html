The Application Layer: HTTP, HTTPS, DNS, Email, CDNs

The application layer is the top layer, the one your apps speak. These four lectures cover the protocols you use every day without noticing.

Lecture 5 — HTTP/1.1 → HTTP/2 → HTTP/3, client–server vs P2P, REST

HTTP is a simple ask-and-answer protocol: the browser sends a request, the server sends back a response. Each new version makes loading many files at once faster.

HTTP: the web's language

HTTP (HyperText Transfer Protocol) is a stateless request–response protocol.

  • Request–response: the client (browser) sends a request; the server processes it and sends back a response.
  • Stateless: each exchange is independent. The server remembers nothing between requests.

Cookies and session tokens. The server gives your browser a small ID (a cookie). The browser sends that ID back with every request, so the server can look up who you are. The memory lives in the cookie and the server's database, not in HTTP itself.

Non-persistent vs persistent connections

HTTP runs on top of a TCP connection. A web page is many files (HTML, CSS, JS, images). The question is whether each file gets its own TCP connection.

Non-persistentPersistent (keep-alive)
RuleOpen a TCP connection, fetch one object, close it. Repeat for every object.Open one TCP connection and keep it open for many objects.
Cost per objectAbout 2 RTTs: 1 for the TCP handshake + 1 for request and responseAbout 1 RTT after the first (no new handshake)
Used byHTTP/1.0HTTP/1.1 (default) and later

RTT = round-trip time: the time for a small packet to go to the server and come back.

A page has 1 HTML file and 10 images. Count RTTs (ignore file transfer time, no parallel connections).

Non-persistent: 11 objects × 2 RTT = 22 RTT.
Persistent: 1 RTT handshake once + 11 objects × 1 RTT = 12 RTT.

Head-of-line (HoL) blocking

Head-of-line blocking means: the item at the front of a queue is slow, so everything behind it waits even though it is ready.

In HTTP/1.1, responses on one connection must come back in the same order as the requests (FIFO: first in, first out). If the first response is a slow image, the CSS, JS, and icon behind it are all stuck.

The evolution: HTTP/1.0 → 1.1 → 2 → 3

You order an outfit: shirt, pants, shoes, socks. These are your HTML, CSS, JS, and images.

  • HTTP/1.0: the truck carries one item per trip and returns to the warehouse before the next. A new connection for every file.
  • HTTP/1.1: the truck arrives with all four items (keep-alive) but unloads them one by one, in order.
  • HTTP/2: the whole tray is served at once and you pick what to eat first. Many items share one trip without waiting in line.
  • HTTP/3: every item you order has its own kitchen window and its own staff. A delay on one does not touch the others.

HTTP/1.0 (1996)

  • One request per TCP connection. No persistent connection. Slow and repetitive.

HTTP/1.1 (1997)

  • Persistent (keep-alive) connections, caching headers, and the Host header.
  • Still has head-of-line blocking: one request at a time per connection.
  • Workaround used by browsers: open about 6 parallel TCP connections per site to fake parallelism. Costly: 6× the setup, 6× the overhead.
  • Pipelining (optional): send several requests without waiting for each response. But responses must still arrive in order (FIFO), and only safe methods (GET, HEAD, OPTIONS) may be pipelined, not POST/PUT, because those change things on the server. Rarely used in practice.

HTTP/2 (2015)

  • Uses a single TCP connection.
  • Binary protocol: messages are encoded as binary frames (the "framing layer"), not text.
  • Multiplexing: many requests and responses are in flight at once, as separate streams on the one connection. Their frames are interleaved, so a slow response no longer blocks the others. This fixes HoL blocking at the HTTP level.
  • HPACK: header compression. Headers repeat a lot (same cookies, same user agent), so they are sent in compressed form.
  • Server push: the server can send files it knows you will need before you ask.
  • Remaining problem: everything rides on one TCP connection, and TCP delivers bytes strictly in order. If one TCP segment is lost, all streams stall until it is re-sent. This is TCP-level HoL blocking.

HTTP/3 (2022)

  • Runs over QUIC, a transport protocol built on UDP instead of TCP (first developed at Google).
  • QUIC gives each stream its own ordering. A lost packet delays only its own stream. HoL blocking is gone.
  • Faster setup: QUIC combines the connection handshake and the TLS 1.3 encryption handshake. A new connection needs 1 RTT; a repeat visit can send data with 0 RTT. (TCP + TLS 1.3 needs 2 RTTs.)
  • Encryption is built in and always on.

APIs and REST

Browsers talk to servers, but apps also need to talk to other apps (your food-delivery app asks a maps service for a route). They do this through an API (Application Programming Interface): a defined set of requests one program can make to another.

REST (Representational State Transfer) is the most common style for web APIs. A 2024 analysis estimated about 83% of public APIs use it. Its principles:

  1. Resources. Everything is a resource (a user, an order, a photo) with its own URL, such as /users/42. URLs are nouns, not verbs.
  2. HTTP methods as CRUD. You act on a resource using the standard methods.
  3. Statelessness. Each request carries everything the server needs (for example a login token). The server keeps no memory of earlier requests.

Data is usually sent as JSON. OpenAPI (Swagger) is a standard way to document a REST API, as shown in class with the Petstore demo.

Check yourself

What does "HTTP is stateless" mean, and how do websites remember you anyway?

The server keeps no memory between requests; each one is independent. Websites use cookies or session tokens that the browser sends with every request.

What are the three parts of an HTTP request line?

Method, URL, HTTP version. Example: GET /index.html HTTP/1.1.

Match: 200, 301, 404, 500.

200 OK (success). 301 Moved Permanently (redirect). 404 Not Found (client error). 500 Internal Server Error (server error).

A page has 1 HTML file and 5 images. How many RTTs with non-persistent HTTP, and with persistent HTTP?

Non-persistent: 6 × 2 = 12 RTT. Persistent: 1 + 6 = 7 RTT.

HTTP/2 multiplexes streams. Why does it still suffer from head-of-line blocking?

All streams share one TCP connection. TCP delivers bytes in order, so one lost segment holds back every stream until it is re-sent. That is TCP-level HoL blocking.

How does HTTP/3 remove HoL blocking?

It runs on QUIC over UDP. QUIC handles each stream independently, so a lost packet delays only the stream it belongs to.

Which HTTP method would a REST API use to update an existing order?

PUT (for example PUT /orders/17).

Give one advantage and one disadvantage of P2P over client–server.

Advantage: self-scaling and no central server to fail or pay for. Disadvantage: harder to manage and secure; availability depends on peers that come and go.

Lecture 6 — HTTPS and the TLS handshake

HTTPS is ordinary HTTP sent through an encrypted tunnel called TLS, so nobody in between can read it, change it, or pretend to be the website.

Why HTTP is not enough

HTTP sends everything as plain text. Anyone who can capture the traffic (someone on the same café WiFi, your ISP) can read your password and see exactly what you send and receive.

HTTPS = HTTP + TLS

TLS (Transport Layer Security) is the protocol that does the encrypting. Its older name was SSL (Secure Sockets Layer); people still say "SSL certificate" out of habit.

What does the 🔒 in the browser mean?

  • Safe website? ✗ No. A scam site can have a padlock too.
  • Encrypted connection? ✓ Yes.
  • Verified identity (you really are talking to that domain)? ✓ Yes.

The three goals

Cryptography is the practice of turning readable text (plaintext) into unreadable code (ciphertext) and back.

GoalMeaningShort form
ConfidentialityOnly the intended parties can read the dataNo eavesdropping
IntegrityThe data has not been changed on the wayNo tampering
AuthenticationYou are really talking to who you think you areVerified identity

Symmetric vs asymmetric encryption

Encryption scrambles data using a key. Decryption unscrambles it.

SymmetricAsymmetric (public-key)
KeysOne shared secret key. The same key locks and unlocks.A pair: a public key (give it to everyone) and a private key (never leaves the owner). What one locks, only the other unlocks.
SpeedFastSlow (heavy maths)
ProblemHow do two strangers share the key safely? If you send it over the network, an eavesdropper gets it too.Too slow to encrypt all the data
ExamplesAES, ChaCha20RSA, Diffie–Hellman / ECDHE
AnalogyOne house key that both of you need a copy ofA letterbox: anyone can drop a letter in (public), only the owner's key opens it (private)

Asymmetric is used briefly at the start to agree on a secret safely. Symmetric is then used for all the actual data, because it is fast.

Why not only symmetric? Strangers cannot securely share a key. Why not only asymmetric? Too slow. So TLS uses asymmetric to bootstrap a symmetric session key.

Certificates and the chain of trust

Encryption alone does not help if you are encrypting to the wrong party. How do you know the public key really belongs to microsoft.com and not to a look-alike such as micrоsоft.com (with Cyrillic "о" letters)?

A certificate is a digital ID card. It says: "this domain name owns this public key", and it is digitally signed by a Certificate Authority (CA), a company that browsers trust (DigiCert, Let's Encrypt, Amazon).

A certificate contains: the domain name, the public key, who issued it, the validity dates, and the CA's signature.

The browser validates a certificate by checking: Is the chain signed correctly up to a trusted root? Does the name match the site I asked for? Is it within its dates? Has it been revoked? If any check fails, you see the "Your connection is not private" warning.

Man-in-the-middle (MITM) attack

An attacker sits between you and the server, relays messages both ways, and reads or changes them. To you they pretend to be the server; to the server they pretend to be you.

How TLS defeats it: the attacker must present a certificate for bank.com. They cannot get one signed by a trusted CA, because CAs only issue to the real domain owner. And they cannot reuse the bank's real certificate, because they do not have the matching private key. So certificate validation fails and your browser warns you.

  • ACM issues public TLS certificates for free and renews them automatically. No manual installing or expiry reminders.
  • You attach the certificate to a load balancer (or CloudFront), not to each server.
  • TLS termination: the load balancer does the TLS handshake and decryption. Clients speak HTTPS to the load balancer; the load balancer can speak plain HTTP to the servers behind it inside the private network.

Check yourself

What are the three security goals of TLS?

Confidentiality (no eavesdropping), integrity (no tampering), authentication (verified identity).

Why does TLS use both asymmetric and symmetric encryption?

Symmetric is fast but needs a shared key, and strangers cannot share one safely. Asymmetric solves the sharing but is slow. So TLS uses asymmetric once to establish a symmetric session key, then uses symmetric for the data.

What does a certificate bind together, and who signs it?

It binds a domain name to a public key. It is signed by a Certificate Authority (CA).

Write the chain of trust in order.

Leaf (the site's certificate) → Intermediate CA → Root CA (trusted by the browser/OS).

List the TLS handshake steps.

ClientHello → ServerHello + Certificate → Authentication (certificate validation) → Key exchange → Finished, then symmetric encryption begins.

Which handshake step defeats a man-in-the-middle attack, and why?

Certificate validation. The attacker cannot present a certificate for the real domain signed by a trusted CA with a matching private key.

Does the padlock mean the website is safe?

No. It means the connection is encrypted and the server's identity for that domain is verified. A phishing site can also have a valid certificate for its own domain.

What is TLS termination?

Ending the TLS connection at a load balancer: it handles the handshake and decryption (using an ACM certificate) and forwards the request to the backend servers.

Lecture 7 — DNS: the Internet's phone book, and AWS Route 53

Computers find each other by number (IP address), people remember names. DNS is the system that turns a name like amazon.com into its number.

The DNS lecture file was not in the class folder. This section follows the syllabus bullets, the DNS recap slides shown at the start of Lecture 9, and the course textbook (Kurose & Ross, section 2.4). If your instructor used different examples, add them here.

What DNS does

DNS = Domain Name System. It translates names → IP addresses, like a phone book turns a person's name into a phone number.

  • DNS runs first, before the TCP handshake and before TLS. Your browser cannot connect to a name; it needs the IP address.
  • It is a distributed database: no single computer holds all names. The data is spread over many servers arranged in a hierarchy.
  • DNS is an application-layer protocol that normally uses UDP port 53 (one small question, one small answer, so no need for a connection).

The hierarchy

Read a domain name from right to left: www.amazon.com → .com → amazon → www.

LevelWhat it knowsWhat it answers
Root serversWhere the TLD servers are"I don't know amazon.com, but here are the .com servers."
TLD servers
(Top-Level Domain: .com, .org, .in)		Which authoritative servers handle each domain under that TLD"I don't know www.amazon.com, but here are amazon.com's name servers."
Authoritative name serversThe actual records for one domain. Run by the domain's owner or their DNS provider (e.g. Route 53)."www.amazon.com is at 205.251.242.103." This is the final answer.

One more player, outside the hierarchy: the recursive resolver (also called the local DNS server). It is run by your ISP or a public service (Google 8.8.8.8, Cloudflare 1.1.1.1). Your device asks it, and it does the searching for you.

How a lookup works

You type www.amazon.com. Assume nothing is cached.

  1. Your laptop asks the recursive resolver: "What is the IP of www.amazon.com?"
  2. The resolver asks a root server.
  3. Root replies with a referral: "Ask the .com TLD servers; here are their addresses."
  4. The resolver asks a .com TLD server.
  5. TLD replies with a referral: "Ask amazon.com's authoritative servers; here they are."
  6. The resolver asks the authoritative server for amazon.com.
  7. The authoritative server replies with the answer: the IP address.
  8. The resolver returns the IP to your laptop and caches it. Now the browser can start the TCP handshake.

Recursive: you ask a receptionist for someone's desk number, and they make all the phone calls and come back with the answer. Iterative: each person you ask says "not me, try the second floor", and you walk there yourself.

DNS record types

A DNS server stores resource records. Each has a name, a type, a value, and a TTL.

TypeMapsExample

An A record points to an IP address. A CNAME points to another name, which must then be looked up again. A CNAME cannot be placed at the bare domain (example.com), only on sub-names like www.

Caching and TTL

If every lookup went through all eight steps, the Internet would be slow and the root servers would melt. So answers are cached (remembered) at several places: your browser, your operating system, and the recursive resolver.

Every record carries a TTL (Time To Live): the number of seconds a cache may keep it. A TTL of 300 means "you may reuse this answer for 5 minutes, then ask again".

You move your website to a new server and update the A record. Your authoritative server gives the new IP immediately. But resolvers all over the world still hold the old answer in cache until its TTL runs out. If the TTL was 86,400 seconds, some users are sent to the old server for up to 24 hours.

Trade-off: a long TTL means fewer lookups and faster browsing but slow changes. A short TTL means fast changes but more queries. Tip: lower the TTL a day before a planned move.

Route 53 is AWS's managed DNS service (53 is the DNS port). You create a hosted zone for your domain and put records in it. Route 53 then acts as the authoritative name server.

A routing policy decides which answer Route 53 gives when one name has several possible targets:

PolicyWhat it doesUse it when
SimpleOne name → one answer. No logic.You have a single server
WeightedSplits traffic by weights you set (e.g. 90% / 10%)Testing a new version on a small share of users

Check yourself

Why must DNS run before the TCP handshake?

TCP connects to an IP address, not a name. DNS provides the IP address for the name the user typed.

Name the three levels of the DNS hierarchy and what each returns for www.amazon.com.

Root: the addresses of the .com TLD servers. TLD: the addresses of amazon.com's authoritative servers. Authoritative: the IP address of www.amazon.com.

What is the difference between a recursive and an iterative query?

Recursive: the server asked must return the final answer, doing all further lookups itself. Iterative: the server returns either the answer or a referral to the next server, and the asker continues.

Which record would you create to: (a) point a name to 13.233.5.10, (b) make blog.site.com an alias of site.com, (c) say where email for the domain goes?

(a) A record. (b) CNAME record. (c) MX record.

What is a TTL, and what happens if it is very long?

The number of seconds a cached DNS answer may be reused. A very long TTL reduces queries but makes DNS changes take a long time to reach all users.

You run the app in Mumbai and Virginia and want each user sent to whichever responds faster. Which Route 53 policy?

Latency-based routing.

You want a standby site to take over automatically when the main site is down. Which policy?

Failover routing (with a health check on the primary).

Which transport protocol and port does DNS normally use?

UDP, port 53.

Lecture 8 — Email protocols (SMTP, POP3, IMAP), CDNs and caching

Email uses one protocol to send and another to read. Caching and CDNs make the web fast by keeping copies of content close to the user.

How email travels

Three kinds of component:

  • Mail User Agent (MUA): the app you read and write mail in (Gmail app, Outlook).
  • Mail Transfer Agent (MTA): a mail server that moves mail between servers.
  • Mailbox: where your incoming mail is stored on your mail server.
  1. Alice's mail app connects to her mail server using SMTP and hands over the message.
  2. Her server uses SMTP again to push the message to Bob's mail server. (It finds that server by a DNS MX lookup.)
  3. The message waits in Bob's mailbox.
  4. Bob's mail app fetches it using POP3 or IMAP.

SMTP — Simple Mail Transfer Protocol

  • Sends email: from client to server, and from server to server.
  • It is a push protocol: the sender starts the transfer.
  • Uses TCP. Ports: 25 (server to server), 587 (your app submitting mail, with encryption), 465 (older encrypted port).
  • Real world: SendGrid, Mailchimp, Mailgun are SMTP relay services that apps use to send mail.

POP3 — Post Office Protocol version 3

  • Downloads mail to your device and then deletes it from the server.
  • One-way: server → client.
  • Good for offline reading on one device. Bad for several devices, because nothing is synced.
  • Port 110; secure version (POP3S) 995.

IMAP — Internet Message Access Protocol

  • Mail stays on the server; your app views and manages it there.
  • Two-way sync: mark as read, move to a folder, or delete on your phone, and your laptop shows the same.
  • Supports folders (Inbox, Sent, Drafts) and partial downloads (headers first).
  • Port 143; secure version (IMAPS) 993.

Web caching

Caching means storing a copy of data in a fast, nearby place so that the next request for the same data is answered quickly, without going back to the original, slower source.

  • Cache hit: the copy is in the cache. Serve it immediately.
  • Cache miss: not in the cache. Fetch from the original server (the origin), store a copy, then serve.

There are layers of caching between you and the origin:

Cache-Control: how long is a copy fresh?

The server tells caches what they may do using the Cache-Control response header.

Cache-Control: public, max-age=3600
  • max-age=3600: this copy is fresh for 3,600 seconds (1 hour). During that hour the browser uses it without contacting the server at all.
  • public: any cache (browser, proxy, CDN) may store it. private: only the user's own browser may. no-store: never cache (bank pages).

ETag: is my old copy still correct?

When the copy has expired, the browser does not have to download the whole file again. It can ask "has it changed?". This is called revalidation or a conditional GET.

  • An ETag is a version label (a fingerprint) the server attaches to a file, e.g. ETag: "abc123".
  • Later the browser sends If-None-Match: "abc123", meaning "send the file only if its tag is no longer abc123".
  • If unchanged, the server replies 304 Not Modified with no body. The browser reuses its copy. Small and fast.
  • If changed, the server replies 200 OK with the new file and a new ETag.

Content Delivery Networks (CDNs)

Instead of travelling to faraway farms, shoppers visit a local store. The local stores stock food from the distant farms. A CDN does the same for web content: it keeps copies close to users, so pages load in milliseconds instead of crossing the world.

A CDN is a set of geographically distributed servers, called edge servers, that cache content near users.

  1. A user requests content (a video, an image).
  2. The nearest edge server answers instead of the origin.
  3. If the edge does not have it (cache miss), it fetches it from the origin, caches it, and serves it.

Benefits: lower latency (shorter distance, so less propagation delay), less bandwidth and load on the origin, and better availability (if one edge fails, another serves).

Pull vs push caching

Pull CDNPush CDN
How content gets to the edgeThe edge fetches it from the origin the first time a user asksYou upload it to the edges in advance
First requestSlow (a cache miss)Fast (already there)
EffortLow: automaticHigher: you manage what is where
Good forWebsites with lots of ordinary contentLarge files known in advance: a film release, a game update

How does the user reach the nearest edge? DNS-based steering

The website's name is a CNAME pointing to the CDN's name. When your resolver asks the CDN's DNS server, that server looks at where the question came from and replies with the IP address of an edge server near you. Users in Delhi and London ask for the same name and receive different IP addresses.

Facts from class:

  • CDNs appeared in the late 1990s; Akamai pioneered them in 1998.
  • Major CDNs: Akamai, Cloudflare, Amazon CloudFront, Google Cloud CDN, Azure CDN, Fastly.
  • Netflix Open Connect: Netflix puts its own storage appliances inside ISPs' buildings. One appliance holds up to 350 TB.
  • Fastly outage, June 2021: one misconfiguration at Fastly took down Reddit, Amazon, The New York Times and others. It showed how much of the web depends on a few CDNs.
  • CloudFront is AWS's CDN. Its edge servers sit in Edge Locations, which are far more numerous than Regions.
  • You set an origin (an S3 bucket, an EC2 server, or a load balancer). CloudFront works as a pull CDN: the first request to an edge is fetched from the origin and cached.
  • How long the edge keeps a copy follows the origin's Cache-Control header or the TTL you set.

Check yourself

Which protocol sends email, and which two retrieve it?

SMTP sends (push). POP3 and IMAP retrieve.

You read email on a phone and a laptop and want both to show the same folders and read status. POP3 or IMAP? Why?

IMAP. Mail stays on the server and changes sync to every device. POP3 downloads to one device and deletes from the server.

Give the port numbers for SMTP, POP3, and IMAP.

SMTP 25 (and 587 for submission). POP3 110 (995 secure). IMAP 143 (993 secure).

What is the difference between a cache hit and a cache miss?

Hit: the cache already has a valid copy and serves it. Miss: it does not, so the request goes to the origin and the result is stored.

What does Cache-Control: public, max-age=600 mean?

Any cache may store the response, and it is fresh for 600 seconds (10 minutes).

A browser sends If-None-Match: "v7" and the file has not changed. What does the server reply?

304 Not Modified, with no body. The browser reuses its cached copy.

How does a CDN reduce delay? Link it to Lecture 2.

It serves content from an edge server near the user, which shortens the distance d, so propagation delay d/s falls. It also takes load off the origin.

Pull CDN vs push CDN in one line each.

Pull: the edge fetches from the origin on the first request. Push: you upload content to the edges beforehand.
