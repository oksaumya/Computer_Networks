Lecture 9 — Multiplexing, ports, UDP, and the TCP connection

The network layer gets data to the right computer. The transport layer gets it to the right program on that computer, using port numbers.

What the transport layer does

The transport layer turns application messages into segments. Routers in the middle only read network-layer information; they ignore the transport header completely.

Ports and sockets

To send a letter to a friend in a big apartment building you need two things: the building's street address and the apartment number. Without both, the letter is lost.

🏢 IP address = the computer's street address (e.g. 172.217.167.78).
🚪 Port number = the application's apartment number (e.g. port 443).

  • A port is a 16-bit number (0 to 65,535) that identifies one application on a computer.
  • IP address + port number = socket: one unique endpoint, a specific "doorway" on a computer. Written 172.217.167.78:443.
  • Example: your browser connecting to Google is your laptop IP : random port ↔ Google IP : 443.
  • To see listening ports on Linux: netstat -tnlp.

Multiplexing and demultiplexing

Your laptop runs a browser, Spotify, and WhatsApp at once, all sharing one network connection.

  • Multiplexing (sender side): collect data from many application processes, label each piece with port numbers, and send them all down through the one network layer.
  • Demultiplexing (receiver side): look at the port number in each arriving segment and deliver it to the correct application process.
UDP demultiplexingTCP demultiplexing
Socket identified by2-tuple: destination IP, destination port4-tuple: source IP, source port, destination IP, destination port
EffectAll senders to the same port land in the same socketEach client gets its own connection, even when all go to port 443

Two tabs in your browser open the same site. Both go to 142.250.72.14:443, from the same laptop IP. The only difference is the source port (say 51000 and 51001). Because TCP uses all four values, the server sees two separate connections and never mixes up the replies.

UDP — User Datagram Protocol

UDP's attitude, from the class slide: the receiver asks "Are you getting all of this?", and UDP answers "Who cares, just send it faster!"

  • Connectionless: no handshake. Just send.
  • No ACKs (no confirmations), no retransmission, no ordering, no flow or congestion control.
  • Delivery is "best effort": segments may be lost, duplicated, or arrive out of order.
  • Tiny header: 8 bytes, four fields.
UDP header field (16 bits each)Purpose
Source portWhich application sent it
Destination portWhich application should receive it
LengthSize of header + data
ChecksumDetects corrupted bits

Where UDP is used, and why:

  • DNS: one small question, one small answer. A handshake would double the time. If the reply is lost, just ask again.
  • Live video / live streaming (cricket, news, gaming): speed matters more than perfection. If some frames are lost they are skipped. Waiting for a re-send would freeze the picture.
  • VoIP (voice calls) and online games: same reason. Old data is useless.
  • QUIC / HTTP/3: builds its own reliability on top of UDP.

TCP — Transmission Control Protocol

  • Connection-oriented: the two sides set up a connection (handshake) before sending data, and close it afterwards.
  • Reliable: lost data is detected and re-sent. Uses sequence numbers, acknowledgments, and checksums.
  • In-order byte stream: the application receives exactly the bytes that were sent, in the same order, with no gaps and no duplicates.
  • Also does flow control (Lecture 10) and congestion control (Lecture 11).

The TCP 3-way handshake

Told from your browser's side, connecting to a Google server (the story from class). Think of a phone call: ring, "hello?", "I'm here".

Client (your browser)Server (Google, port 443)
① SYN seq = 100"Are you there? I'd like to talk. I'll number my data starting at 100."
② SYN-ACK seq = 350, ack = 101"Yes, I'm here. I got your 100, send 101 next. I'll number mine starting at 350."
③ ACK ack = 351"Got it. You start at 350, I expect 351 next. Let's talk."
Connection ESTABLISHED — data can flow both ways
  • SYN = "synchronize". It means "let's synchronize our sequence numbers".
  • ACK = "acknowledgment". The ack number is always the next number I expect from you. That is why seq 100 is answered with ack 101.
  • Each side picks its own starting sequence number (called the ISN, initial sequence number). They are random in real life; 100 and 350 are just the class example.

Both sides must (a) announce their own starting number and (b) hear that the other side received it. Step ① does (a) for the client. Step ② does (b) for the client and (a) for the server. Step ③ does (b) for the server. With only two steps the server would never know its own SYN arrived.

Connection teardown — a 4-step goodbye

ClientServer
① FIN"I have to go." (I have no more data to send)
② ACK"Okay."
server may still finish sending its remaining data
③ FIN"I'm done too."
④ ACK"Bye."
Connection CLOSED

FIN = "finish". Each direction is closed separately, which is why it takes four messages: FIN, ACK, FIN, ACK.

How TCP keeps order and reliability (preview of Lecture 10)

  • Sequence numbers → ordered delivery. Packets can take different routes and arrive out of order: "the mat." "The cat" "sat on". Every segment carries a number. If #3 arrives before #2, the receiver holds it until #2 comes, then hands the data to the app in order.
  • Acknowledgments + retransmission → reliability. On a phone call you know the other person heard you when they say "hmm" or "achcha". When the server receives bytes 101–200 it sends an ACK saying "I've received everything up to 200; send 201 next". If the sender gets no ACK within a set time, it assumes the data was lost and re-sends it.

Ask one question: is late data still useful?

  • Every byte must arrive, and a short wait is fine (a bank transfer, a file, an email, a web page) → TCP.
  • Data must be on time, and a little loss is fine (a live call, a live match, a game) → UDP.
  • Tiny one-shot question and answer (DNS) → UDP.

A DNS exchange is one small request and one small reply. A TCP handshake would add a round trip of delay for no benefit; if the reply is lost the client simply asks again.

Lecture 10 — Reliable data transfer (Go-Back-N, Selective Repeat) and TCP flow control

Reliability is built from a few simple tools: number every packet, confirm what arrived, and re-send what did not. The protocols differ only in how much they re-send.

Building reliability from an unreliable channel

The network below can corrupt bits, lose packets, and reorder them. Each problem has a tool:

Checksum, worked through

The idea: the sender adds up the data and sends the (flipped) sum along with it. The receiver adds everything up again. If the result is not what it should be, bits were damaged.

Alice sends two chunks: 10010011 (147) and 01010110 (86).

  10010011
+ 01010110
----------
  11101001      ← the sum (233). No carry out of the 8th bit this time.

Flip every bit (this is called the 1's complement): checksum = 00010110.

Receiver (Bob) adds the two chunks and the checksum: 11101001 + 00010110 = 11111111. All 1s → no error detected ✅. Any 0 in the result means the data was damaged.

Chunks 11010011 (211) and 01010110 (86).

  11010011
+ 01010110
----------
1 00101001      ← 9 bits: a carry came out of the top
  00101001
+        1      ← wrap the carry around: add it back to the result
----------
  00101010      ← the sum

Flip the bits: checksum = 11010101. Check: 00101010 + 11010101 = 11111111 ✅.

The class slides use the first pair of numbers but show a sum of 00001001 with a carry, giving checksum 11110101. If you add 147 + 86 by hand you get 233 = 11101001 with no carry, so the checksum is 00010110. The method on the slide is right (add, wrap any carry, flip the bits); only the arithmetic differs. In the exam, show each step so you get the method marks, and ask your instructor which answer they expect for this pair.

Real TCP and UDP do the same thing with 16-bit chunks.

RTT and the timeout

Round Trip Time (RTT) is the time for a segment to go from sender to receiver plus the time for the ACK to come back. You can measure it with ping newtonschool.co.

The sender must choose how long to wait before deciding a packet is lost. Too short → it re-sends packets that were only slow (a premature timeout, wasteful). Too long → it reacts slowly to real loss. So the timeout is set a little longer than the measured RTT.

Stop-and-wait: correct but slow

The simplest reliable protocol: send one packet, stop, and wait for its ACK before sending the next.

ACK 1"got 0, send me 1"

no ACK arrives → timer expires

It always works, but the sender is idle most of the time, waiting. On a long-distance link, waiting dominates.

Utilization = Tframe / (Tframe + 2 · Tprop)Tframe = transmission time (L/R) · Tprop = one-way propagation delay (d/s)

Packets of 8,000 bits on a 1 Mbps link that is 3,000 km long (signal speed 2 × 10⁸ m/s). What fraction of the time is the sender actually sending?

Tframe = 8,000 ÷ 1,000,000 = 8 ms.
Tprop = 3,000,000 ÷ 200,000,000 = 15 ms.
Utilization = 8 ÷ (8 + 2 × 15) = 8 ÷ 38 ≈ 0.21, or 21%.

The link sits idle 79% of the time.

Pipelining and the window

Pipelining means sending several packets in a row without waiting for each ACK. This fills the idle time and raises utilization.

The sender may not send without limit. It keeps a window: the set of packets it is allowed to have "in flight" (sent but not yet acknowledged). The window size is N. When the oldest packet is ACKed, the window slides forward and a new packet may be sent.

There are two pipelined protocols. They differ in what happens when a packet is lost.

Go-Back-N (GBN)

  • The sender sends up to N packets without waiting.
  • The receiver accepts packets only in order. It has no buffer for out-of-order packets.
  • ACKs are cumulative: "ACK n" means "I have everything up to and including n".
  • If a packet is lost, the receiver discards every packet after it, even correct ones, and keeps re-sending the ACK for the last in-order packet.
  • On timeout the sender goes back and re-sends the lost packet and everything after it in the window.

Selective Repeat (SR)

  • The sender sends up to N packets without waiting (same as GBN).
  • The receiver accepts and buffers out-of-order packets.
  • ACKs are individual: each packet is acknowledged by itself.
  • Each packet has its own timer. On timeout the sender re-sends only that one packet.
  • When the missing packet finally arrives, the receiver delivers it together with everything it had buffered, in order.

Extra fact if asked: with m-bit sequence numbers, the largest safe window is 2m − 1 for GBN and 2m−1 for SR.

A sender has 10 packets (0–9), window N = 4. Only packet 3 is lost, once. Everything else arrives. How many packets are transmitted in total?

Go-Back-N: when packet 3 times out, the window holds 3, 4, 5, 6, so all four are re-sent. Total = 10 + 4 = 14.
Selective Repeat: only packet 3 is re-sent. Total = 10 + 1 = 11.

What real TCP does: a hybrid

  • Cumulative ACKs like GBN ("I have everything up to byte X").
  • But the receiver buffers out-of-order segments like SR, and with the SACK (selective acknowledgment) option it tells the sender exactly which later blocks it already has.
  • Fast retransmit: if the sender sees three duplicate ACKs, it re-sends the missing segment immediately without waiting for the timer (details in Lecture 11).
  • So TCP re-sends only what is missing, like SR.

TCP flow control

Problem: not all devices have the same buffer size or processing power. A fast sender can flood a slow receiver. The receiver's buffer overflows and data is lost.

Solution: the receiver tells the sender how much it can take: "Hey, slow down, I can only handle this much right now."

  • The receiver puts its free buffer space in the Window size field of every segment it sends back. This is the receive window, rwnd ("receiver-advertised window").
  • The sender never has more un-ACKed data in flight than rwnd.
  • As the receiving application reads data, space frees up, rwnd grows, and the sender's window slides forward. This is TCP's sliding window.

The receiver's buffer holds 4,000 bytes. It currently holds 2,500 bytes the app has not read yet. What rwnd does it advertise?

rwnd = free space = 4,000 − 2,500 = 1,500 bytes. The sender may have at most 1,500 un-ACKed bytes outstanding.

Zero window

If the receiver's buffer is completely full it advertises window size = 0. The sender must stop sending data. So that it does not wait forever, the sender periodically sends a tiny window probe; when the receiver has space again it replies with a non-zero window and sending resumes.

Flow control protects the receiver (its buffer). Congestion control protects the network (the routers in between). They are two separate mechanisms with two separate windows: rwnd and cwnd. Lecture 11 covers cwnd.

In Go-Back-N with N = 5, packets 0–4 are sent and packet 1 is lost. Which packets are re-sent after the timeout?

1, 2, 3, 4 (the lost one and everything after it that was sent). The receiver had discarded 2, 3, 4 because they were out of order.

Same situation in Selective Repeat. What is re-sent?

Only packet 1. The receiver buffered 2, 3, 4 and ACKed each of them.

What does "cumulative ACK" mean?

One ACK confirms everything up to a point. "ACK 7" means all packets up to 7 have arrived.

What is rwnd, and who sets it?

The receive window: the free space in the receiver's buffer. The receiver sets it and advertises it in the Window field of the TCP header.

What happens when a receiver advertises a zero window?

The sender stops sending data and sends small window probes from time to time until the receiver advertises a non-zero window.

In what way is real TCP a hybrid of GBN and SR?

It uses cumulative ACKs (GBN-like) but buffers out-of-order segments and can use SACK and fast retransmit to re-send only the missing segment (SR-like).

Lecture 11 — TCP congestion control (slow start, AIMD) and TLS at the transport edge

TCP speeds up carefully while things go well and slows down sharply the moment a packet is lost, so that the network does not jam for everyone.

What is congestion?

Congestion happens when the offered load is greater than the network's capacity: senders together push more data than the routers and links can carry. Router queues grow, so queuing delay rises; then buffers overflow, so packets are lost (Lecture 2).

Flow control helps one slow receiver ("only Mater wants to move slowly"). Congestion is a traffic jam: the road itself is full, so all senders have to slow down.

TCP is a polite driver. Its mission: get your data there as fast as possible, but without causing a traffic jam for everyone else.

The congestion window (cwnd)

  • cwnd is a limit kept by the sender on how much data it may have in flight (sent but not yet ACKed).
  • Nobody tells the sender this number. It guesses the network's capacity and adjusts the guess from what it observes: ACKs arriving = good, loss = too fast.
  • It is measured in MSS (Maximum Segment Size): the largest amount of data, in bytes, that fits in one TCP segment. "cwnd = 4" means four full segments.
  • For a new connection, most operating systems today start with cwnd = 10 MSS. Textbook and exam examples start at 1 MSS.

cwnd = 20 MSS, rwnd = 12 MSS, MSS = 1,000 bytes, RTT = 100 ms. What is the approximate sending rate?

Window = min(20, 12) = 12 MSS = 12,000 bytes = 96,000 bits. One window is sent per RTT: 96,000 bits ÷ 0.1 s = 960,000 bps ≈ 0.96 Mbps. Here the receiver is the limit, not the network.

Phase 1: slow start

The name is misleading. It starts slow but grows exponentially.

  • Begin with a small cwnd (1 MSS in examples).
  • Every RTT in which the packets are ACKed, double cwnd: 1 → 2 → 4 → 8 → 16 …
  • From class: send one car on the road; if it gets through, send two; then four.
  • Purpose: find the usable capacity quickly without knowing it in advance.

Slow start ends when one of two things happens:

  1. cwnd reaches the slow start threshold (ssthresh) → switch to congestion avoidance.
  2. A packet loss occurs (timeout or three duplicate ACKs).
on loss: ssthresh = cwnd / 2half of the congestion window at the moment congestion was detected

Phase 2: congestion avoidance

Past ssthresh, TCP is near the capacity it found last time, so it becomes careful. Instead of doubling, it adds just 1 MSS per RTT: 16 → 17 → 18 → 19 … This is a gentle, linear increase.

AIMD: Additive Increase, Multiplicative Decrease

PartRuleWhen
Additive Increasecwnd = cwnd + 1 MSS per RTTEvery RTT with no loss (probing for more bandwidth)
Multiplicative Decreasecwnd = cwnd × ½When loss is detected by three duplicate ACKs

Increase slowly, decrease fast. Plotted over time, cwnd climbs in a straight line, drops by half, climbs again: the classic sawtooth.

Why AIMD gives fairness: when two connections share a bottleneck and both lose a packet, both halve. The one with the larger window gives up more. Both then add the same +1 per RTT. Repeat this and their windows move closer and closer until they share the link about equally.

TCP CUBIC (awareness only)

Is there a better way than AIMD to probe for bandwidth? CUBIC remembers the window size at which loss last happened (Wmax) and grows the window as a cubic function of time: fast when far below Wmax, slow when close to it. It is the default in Linux and the most common TCP on web servers.

Where TLS and QUIC sit

TLS needs every byte delivered in order, because one missing byte breaks decryption. It gets that from TCP: TLS rides on top of TCP's reliable byte stream.

QUIC re-implements reliability over UDP. UDP gives it nothing but ports, so QUIC itself does acknowledgments, retransmission, flow control, and congestion control, with the same ideas as TCP. Because it does this per stream, one lost packet no longer blocks the other streams (see HTTP/3).

Check yourself

Define congestion in one sentence.

Offered load exceeds network capacity, causing queues to build (delay) and buffers to overflow (loss).

cwnd vs rwnd: who sets each and what does each protect?

cwnd is set by the sender and protects the network. rwnd is set by the receiver and protects the receiver's buffer. The sender uses the smaller of the two.

How does cwnd grow in slow start, and how in congestion avoidance?

Slow start: doubles every RTT (exponential). Congestion avoidance: +1 MSS every RTT (linear).

ssthresh = 12, cwnd = 12, congestion avoidance (fast recovery).

ssthresh = 12, cwnd = 1, slow start.

Why is a timeout treated more harshly than three duplicate ACKs?

Duplicate ACKs prove later segments are still getting through, so congestion is mild. A timeout means nothing is being acknowledged, which suggests severe congestion.

What does AIMD stand for, and what shape does it produce?

Additive Increase (+1 MSS per RTT), Multiplicative Decrease (×½ on loss). It produces a sawtooth.

Why does TLS run over TCP, and what does QUIC do differently?

TLS needs a reliable, in-order byte stream, which TCP provides. QUIC runs over UDP and implements reliability, ordering, and congestion control itself, with TLS 1.3 built in.

Lecture 12 — Cloud load balancing: ALB vs NLB, Elastic Load Balancing, high availability

A load balancer stands in front of many servers and shares requests among the healthy ones, so the site survives both crowds and crashes.

Why a load balancer?

The question from class: 10,000 users are trying to reach your website and one server suddenly crashes. Can the website survive?

A load balancer distributes incoming traffic across multiple servers. Its goals:

  • Scalability: handle more users by adding servers behind it.
  • Availability: if a server dies, send traffic to the others.
  • Manageability: users see one address; you can add, remove, or update servers behind it without anyone noticing.

Elastic Load Balancing (ELB) is the AWS service name. Its two main types differ in how the load balancer makes its decision, which is to say which layer it reads.

Network Load Balancer (NLB) — Layer 4

A postal sorter who reads only the ZIP code, not the letter inside.

  • Works at the transport layer. It sees TCP/UDP packets, not HTTP requests, URLs, or headers.
  • Decides using the 4-tuple: source IP, source port, destination IP, destination port.
  • Benefits: ultra-high throughput, very low latency, preserves the client's source IP, excellent for any TCP/UDP workload.
  • Limitation: it cannot tell company.com/api/users from company.com/images/logo.png, because it cannot read the URL.
  1. Client connects; the NLB receives the TCP/UDP packet.
  2. NLB reads the 4-tuple, e.g. 203.0.113.10 : 51514 → 198.51.100.25 : 443.
  3. It forwards the connection to a healthy backend target, e.g. 10.0.1.10:443.
  4. The client's original source IP is preserved all the way to the server.

Application Load Balancer (ALB) — Layer 7

  • Works at the application layer. It understands HTTP requests, URLs, headers, cookies, and host names.
  • Path-based routing: /api/* → API servers, /images/* → image servers.
  • Host-based routing: shop.company.com → shop servers, blog.company.com → blog servers.
  • TLS termination: HTTPS needs a handshake, encryption, and certificates. The ALB handles all of it, so the servers behind it do not have to.

Target groups and health checks

Problem: if server S1 crashes, how does the load balancer know not to send traffic there?

  • A target group is the set of servers (targets) the load balancer can send to. It is the health-monitoring layer between the load balancer and the servers.
  • A health check is a small test request the load balancer sends to each target at a regular interval, for example GET /health every 30 seconds.
  1. The load balancer sends the probe.
  2. The server responds (e.g. 200 OK).
  3. The load balancer marks the target Healthy.
  4. Traffic continues to it.

If a target fails several checks in a row it is marked Unhealthy and automatically removed: no traffic goes to it. Checks continue; when it passes again it is automatically added back. This is called self-healing.

Elasticity and Auto Scaling Groups

Morning traffic is 500 users; evening traffic is 50,000. Should you keep 100 servers running all day? No.

Elasticity means: increase capacity when demand rises, decrease it when demand falls.

An Auto Scaling Group (ASG) does this automatically. It:

  • launches instances when load goes up (scaling out: EC2-1 → EC2-1, EC2-2, EC2-3),
  • terminates instances when load goes down (scaling in),
  • maintains the desired capacity: if an instance dies, it starts a replacement.

New instances are registered into the target group automatically, so the load balancer starts using them as soon as they pass health checks.

Multi-AZ and high availability

Problem: all your servers are in us-east-1a. A power, network, or storage failure hits that data centre. The whole application is down.

An Availability Zone is a physically separate AWS data centre (us-east-1a, us-east-1b, us-east-1c), each isolated from the others.

High availability (HA) means the service stays available even when components fail. The principle: no single point of failure. ❌ one server, ❌ one AZ, ❌ one database.

What if the load balancer itself fails? An ALB is managed by AWS and is itself deployed across multiple AZs.

At global scale (the "final architecture" slide), the same idea is stacked: a global DNS load balancer (Route 53) → a regional load balancer per Region → load balancers per zone → backend services.

Capstone: one request, end to end

This trace ties Lectures 1–12 together. It is a likely long-answer question.

  1. DNS (Route 53). The browser asks for shop.example.com. The resolver walks root → TLD → Route 53 (authoritative), which returns the load balancer's IP according to its routing policy. Lecture 7
  2. TCP handshake. SYN → SYN-ACK → ACK with the load balancer on port 443. Lecture 9
  3. TLS handshake (ACM). ClientHello → ServerHello + certificate (issued by ACM, attached to the ALB) → validation → key exchange → encrypted. TLS terminates at the ALB. Lecture 6
  4. HTTP routing (ALB). The browser sends GET /api/cart. The ALB reads the host and path and picks the matching target group. Lectures 5, 12
  5. Healthy target. Among the targets in that group, the ALB chooses one that is passing health checks, in any AZ. The Auto Scaling Group keeps enough of them running. Lecture 12
  6. Congestion-controlled response. The server's response travels back over TCP: slow start, then AIMD, limited by min(cwnd, rwnd), with lost segments re-sent. Lectures 10–11
  7. Close. FIN → ACK → FIN → ACK, or the connection is kept alive for the next request. Lecture 9

Check yourself

State the three goals of a load balancer.

Scalability, availability, manageability.

You need to send /api/* to one group of servers and /static/* to another. ALB or NLB? Why?

ALB. Path-based routing needs to read the HTTP URL, which only a Layer 7 load balancer can do. An NLB sees only IP addresses and ports.

You run a multiplayer game server over UDP and need the lowest latency. ALB or NLB?

NLB. It handles TCP/UDP at Layer 4 with very low latency. An ALB handles only HTTP/HTTPS.

What is a health check, and what happens when a target fails it?

A periodic test request (e.g. GET /health every 30 s) from the load balancer to each target. A failing target is marked unhealthy and removed from rotation; it is added back automatically when it passes again.

What is the difference between a target group and an Auto Scaling Group?

A target group is the list of targets a load balancer routes to and health-checks. An Auto Scaling Group creates and removes instances to match demand and keep a desired count.

Why deploy in more than one Availability Zone?

To remove the data centre as a single point of failure. If one AZ fails, instances in another AZ keep serving.

What does TLS termination at the ALB mean?

The ALB performs the TLS handshake and decrypts traffic using its certificate; it then forwards requests to the backends, which do not need to handle TLS themselves.

Put in order: TLS handshake, DNS lookup, HTTP request, TCP handshake.

DNS lookup → TCP handshake → TLS handshake → HTTP request.
